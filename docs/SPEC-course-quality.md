# 스펙: 코스 품질 개선 (동선·일정·메뉴 중복·요청 반영)

> 이 문서는 인터뷰에서 사용자가 답한 내용만 정리한 것이다. 구현 방법의 세부 사항(파일·함수·기준값)은 코드 조사 후 별도로 정한다.

## 1. 목표
프로그램 최적화 중 **코스 품질·정확도**, 그중에서도 **추천 내용의 질**을 높인다.

## 2. 문제 (원인)
1. **동선·일정 구성**: 장소 순서가 비효율적이고, 하루 분량·시간 배분이 어색하다.
2. **식당 메뉴 중복**: 한 코스 안에서 같은 메뉴를 파는 식당이 중복 추천된다.
3. **요청 반영 부족**: 다음 조건이 코스에 제대로 반영되지 않는다.
   - 무장애·반려동물
   - 동행·취향

## 3. 해결 방식
설계 원칙(숫자·사실 판정은 코드, 문장은 LLM)에 따라 **코드와 지시문을 함께** 고친다.

| 영역 | 코드가 하는 일 | 프롬프트·지시문이 하는 일 |
|---|---|---|
| 동선 · 하루 분량 | LLM이 고른 후보를 코드가 순서 재배열하고 하루 분량·시간을 배분해 확정한다 | 동선 효율과 하루 분량에 대한 지시를 보강한다 |
| 식당 메뉴 중복 | 대표메뉴 키워드가 일치하면 중복으로 판정한다 | 메뉴 다양성 규칙을 지시문에 명시한다 |
| 요청 반영 | 무장애·반려동물, 동행·취향 조건이 코스에 반영되도록 한다 | 해당 조건을 반영하라는 지시를 보강한다 |

- 중복 판정 기준은 **대표메뉴 키워드 일치**로 한다. (음식 분류 코드 기준은 쓰지 않기로 했다.)

## 4. 완료 기준
**코드 지표 + 테스트**로 확인한다.
- 동선 총거리 (순서 재배열 전후 비교)
- 하루 시간 배분
- 식당 메뉴 중복 수
- `pytest` 통과
- dev 평가 문항으로 확인

## 5. 범위
- 포함: 동선·일정 개선, 식당 메뉴 중복 방지, 요청 반영 부족(무장애·반려동물, 동행·취향) 개선
- 제외: 속도·비용 최적화, 수집·인덱싱 효율 (이번 인터뷰에서 선택하지 않음)

## 6. 지켜야 할 제약 (프로젝트 CLAUDE.md)
- 코스 규칙 위반(없는 장소 · 거리 초과 · 휴무일 겹침 · 기간 밖 축제)의 합격선은 0건이며 낮추지 않는다.
- 고칠 때는 dev 문항만 본다. holdout은 3주차에 한 번만 돌린다.
- 평가 문장을 퓨샷 예시에 넣지 않는다.
- 바꿀 수 있는 값은 `config.py`에만 둔다.
- 핵심 로직(`rag/` · `graph/` · `tools/` · `ingest/`)은 Streamlit을 import하지 않는다.
- Claude와 OpenAI가 같은 지시문·같은 검색 결과를 받는다. 한쪽 전용 지시문을 만들지 않는다.

## 7. 아직 정해지지 않은 것
- 구체적인 구현 단계 구분 (PRD 14번 기준) — 코드 조사 후 제안
- 지표별 합격 기준값
- 요청 반영 부족의 현재 실패 사례 확인
