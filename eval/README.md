# eval — 평가

## retrieval_set.jsonl (3단계, 검색 평가 30건)

한 줄에 질문 한 건이다.

| 칸 | 뜻 |
|---|---|
| `id` | r01 ~ r30 |
| `query` | 검색기에 넣는 질문 |
| `region` | 검색할 때 주는 지역 조건. "지역 없음" 유형은 `null` |
| `expect_region` | 결과가 나와야 하는 지역 |
| `kind` | 이름·낱말 / 뜻 / 조건 / 축제·시기 / 정답 없음 / 지역 없음 |
| `case` | 정상 / 경계 / 엣지 (2일차 Part3) |
| `split` | 고름(설정을 고를 때 쓰는 20건) / 확인(떼어 둔 10건) |
| `today` | 끝난 행사를 거를 때 쓰는 기준일. 재현되도록 고정한다 |
| `answers` | 정답 목록 `[{"id", "title", "grade"}]`. `grade` 2 = 딱 맞음, 1 = 관련 있음. `[]` 는 정답 없음. 2026-11-12 데이터 기준이며 20일 동결 뒤 보강한다 |

- 평가는 `data/eval/places_2026-11-12.jsonl`(그날의 정제 데이터 사본, git 에 올리지 않음)에 대해 잰다. 수집으로 장소가 늘어도 기준선이 흔들리지 않게 하기 위해서다.
- 이 문장들을 퓨샷 예시에 넣지 않는다. "확인" 10건은 설정을 고를 때 보지 않는다.
- 8단계의 40건(코스 평가, dev 28 / holdout 12)과는 다른 묶음이다.

## 검색 평가 결과 (3단계, 2026-11-13 확정)

평가용 데이터 1,898곳(2026-11-12 사본), 상위 10곳 기준. 정답 없는 질문은 평균에서 뺀다.

| 검색기 | 고름 18건 Recall@10 | 고름 nDCG@10 | 확인 9건 Recall@10 | 확인 nDCG@10 | 질문당 시간 |
|---|---|---|---|---|---|
| BM25 | 0.574 | 0.554 | 0.772 | 0.727 | 2ms |
| 임베딩 (BGE-m3-ko) | 0.721 | 0.717 | 0.675 | 0.685 | 60ms 안팎 |
| 합침 (가중치 0.5) | 0.704 | 0.684 | 0.772 | 0.773 | 25ms |
| **합침 + 재정렬 (후보 30)** | **0.867** | **0.863** | **0.819** | **0.824** | 2.6초 |

- 확정한 설정: 임베딩 `dragonkue/BGE-m3-ko`, 임베딩 가중치 0.5, 재정렬 후보 30곳. 고름용으로 비교했고 바꾼 값은 없다.
  - 가중치·후보 수(`python -m eval.compare_settings`): 재정렬 뒤 0.3 은 0.801, 0.7 은 0.852, 1.0 은 0.864, 후보 20곳은 0.832.
  - 임베딩 모델(`python -m eval.compare_embeddings`): text-embedding-3-small 은 임베딩 단독 0.517, 재정렬 뒤 0.789.
- 바꾸는 기준은 결과를 보기 전에 정했다: nDCG@10 이 0.02 이상 높고, 좋아진 질문이 나빠진 질문보다 많을 때만.
- 확인용은 설정을 확정한 뒤 한 번 돌렸다(`python -m eval.retrieval_eval --split 확인`). 이 결과를 보고 설정을 고치지 않는다.
- 한계
  - 정답은 검색기가 고른 곳만 판정했다(풀링). 고름용은 다른 설정이 찾아낸 정답 9곳을 보강했고 확인용은 보강하지 않았다.
  - 질문 수가 적어 0.01 안팎의 차이는 의미를 두기 어렵다. 고름용과 확인용에서 BM25 와 임베딩의 순서가 서로 다르다.
  - 재정렬 1위 점수는 정답 없는 질문에서 0.019 ~ 0.084, 정답 있는 질문에서도 0.026(r12) · 0.068(r08)이 나온다. 점수 하나로 "찾지 못함" 을 가르기 어렵다(5단계에서 정한다).
- 2026-11-20 수집 마감 뒤 정답을 보강하고 같은 설정으로 다시 잰다.

## 코스 평가셋 (`course_set.jsonl`, 14번 8-1)

40건. 유형은 정상 16 · 경계 8 · 엣지 8 · 공격 8, 분할은 dev 28 / holdout 12(유형마다 holdout 2건 이상). 기준일(`today`)은 모두 2026-11-16(월)로 고정한다.

| 칸 | 뜻 |
| --- | --- |
| `turns` | 사용자 문장. 두 개 이상이면 같은 대화에서 차례로 보낸다(되묻기 이어 받기 · 후속 수정) |
| `expect.kind` | 마지막 답의 종류: `course` · `ask_back` · `abstain` |
| `expect.region` · `place` · `days` · `start_date` | 조건 이해가 맞았는지 코드로 비교한다 |
| `expect.missing` | 되묻기 사유 코드. 적힌 것이 모두 들어 있으면 통과 |
| `expect.museum_max` · `notice_has` · `text_has` · `text_not` · `title_has` · `title_not` | 답 안에 있어야 · 없어야 하는 것 |
| `expect.mode` · `changed` | 후속 수정 문항: 수정 경로를 탔는지, 지정한 칸이 바뀌었는지 |
| `expect.exclusions` | 제외 조건. 식당 소개글과 맞는지는 근거성 채점(8-4)에서 본다 |

- 코스가 나온 문항은 모두 규칙 위반(없는 장소 · 거리 초과 · 휴무일 겹침 · 기간 밖 축제) 0건이어야 한다. 문항마다 따로 적지 않는다.
- 평가 문장은 지시문과 시연 버튼 문장에 없어야 한다(`tests/test_course_set.py`가 검사).
- 간접 인젝션(소개글 안의 지시)은 데이터를 고쳐야 해서 9단계 공격 평가셋에서 다룬다.
- 고칠 때는 dev 만 본다. holdout 은 설정을 동결한 뒤 한 번만 돌린다.
